The independent 2.0 source was checked locally on Windows with Python 3.12 and
Godot 4.7. After the research-context and source-extraction corrections, the full
run passed 63 tests, including actual engine import,
main-scene instantiation and a deliberately invalid script reported as failure.
The sample scene driver verifies loading only, not gameplay or visual quality.

An isolated copy of the existing Coin Catch project completed the new task
workflow, including acknowledgment, two actual engine test suites, task closure
and an unreviewed lesson observation. Its original suites passed 308 assertions.
The active space game and the previous framework source binding were unchanged.

Two public sources were fetched and retained with provenance. An actual raw-HTML
indexing attempt exposed 1168 mostly navigational fragments and was stopped.
Article/commit extraction reduced this same input to 11 fragments. The pinned
cached 384-dimensional multilingual model successfully indexed all 11 points
into a new local Qdrant collection and returned six query results. The incomplete
raw-HTML test collection was removed; the previous user collections were retained.
The database listens on loopback. This run did not upload content to Qdrant Cloud;
cloud/federation contracts are covered by explicit test clients, not treated as
live cloud-service verification.

Both corrections used the new framework's actual proposal, bounded snapshots,
source audit, complete test suite, isolated game regression and acceptance path.
The retry-context fix retained its accepted record before the subsequent
extraction proposal. Runtime evidence stays outside the public source tree.

The suite covers task input freshness, exact completion markers, modified logs,
review freshness, preserved failure attempts, research-before-retry, bounded
rollback, damaged snapshots, source-version isolation, public indexing inputs,
partial upload receipts and federated deduplication. Database contract tests use
explicit test clients; they are not evidence of cloud-service availability.

The repository's GitHub workflow defines a Windows/Linux, Python 3.10/3.12
matrix. Those cloud environments are not claimed as passing before actual CI
results exist. No controlled model-quality or token-saving benchmark has run.

Version 1's much larger test count belongs to its different source and API and
is not claimed as coverage of this independent implementation. The migration
boundary and removed bundled components are documented in [design](design.md).
